# 일정·할 일 연결 회귀 테스트

명세서 7장은 일정과 할 일의 연결을 **「이 앱에서 두 번째로 중요한 개념」** 으로 규정한다.
여기가 깨지면 제품의 뿌리가 흔들린다.

이 테스트가 생긴 계기는 실제 사고다. `parentEventID` 가 조용히 `NULL` 로 지워져
두 할 일의 연결이 사라졌고 **복구할 수 없었다.** (BL-045) 화면 오류가 아니라 DB에서 값이
없어진 것이라 눈으로는 알아챌 방법도 없었다. 앞으로는 어떤 수정을 하든 자동으로 검증된다.

## 실행

```
./Tests/run-link-tests.sh                # 앱 빌드 + 전체 (권장)
./Tests/run-link-tests.sh --no-app-build # 로직·영속성만 (빠름)
```

실패하면 종료 코드가 0이 아니다.

## 언제 돌리나

**반드시:**

- `ManagedTask` · `TaskResolution` · `TaskLinkPolicy` · `TaskEditorView` · `EventEditorView`
  를 건드린 뒤
- 일정 삭제·수정, 반복 일정 회차, EventKit 변경 감지에 손댄 뒤
- SwiftData 스키마를 바꾼 뒤 (마이그레이션이 연결을 날리지 않는지)
- **커밋 전**

**권장:** 매 작업 단위가 끝날 때마다. 통째로 20초쯤 걸린다.

## 구성

| 파일 | 역할 |
|---|---|
| `run-link-tests.sh` | 앱 타겟 빌드 → 실제 소스 컴파일 → 로직 → `kill -9` 영속성 |
| `LinkIntegrityTests.swift` | 시나리오 본문 |

**앱 소스를 그대로 컴파일한다.** 사본이나 흉내가 아니라 앱이 쓰는 바로 그
`ManagedTask` · `TaskLinkMaintenance` · `TaskLinkPolicy` 를 부른다.
로직을 고치고 테스트를 안 고치면 곧바로 빨개진다 — 그게 목적이다.

`TaskLinkMaintenance.sync` 가 부모 조회를 클로저로 받도록 설계돼 있어서
캘린더 권한 없이도 실제 로직을 돌릴 수 있다.

## 검사 항목 (96건)

- **기본 동작** — 연결 저장, 부모 이동 추종(offset 불변), 조회 실패 시 연결 보존·`dueAt` 폴백·알림, 부모 복귀
- **해제 판단** — 「특정 날짜」를 고른 경우에만 해제. 부모 미해결 저장은 저장값을 건드리지 않음
- **대량 처리** — 20개 연결, 20개 일괄 삭제 후 일정 보존, 일정 삭제 시 딸린 20개 처리, 여러 일정 중 하나만 삭제
- **반복 실행** — `sync` 100회 연속, 3회에 1회 간헐적 조회 실패
- **경계 조건** — offset 0 / 365일, 반복 일정 회차별 연결, 특정 회차만 삭제, 캘린더가 다를 때, 읽기 전용 캘린더
- **영속성** — 연결 직후 / 부모 이동 직후 `kill -9` → 재실행 시 유지

영속성 테스트는 **임시 위치**에 스토어를 만든다. 사용자의 실제 App Group 스토어는
건드리지 않는다.

## 테스트가 진짜 잡는지 (변이 검증)

테스트는 "통과한다"가 아니라 "**깨지면 빨개진다**"가 증명돼야 쓸모가 있다.
BL-045 버그를 일부러 되살려 확인했다.

| 되살린 버그 | 결과 |
|---|---|
| `sync` 가 조회 실패 시 연결을 끊도록 되돌림 | **11건 실패** |
| 부모 미해결 저장 시 연결을 끊도록 되돌림 | **1건 실패** |

## 연결을 끊는 코드 경로

`parentEventID` 를 `nil` 로 만드는 곳은 앱 전체에서 **하나뿐이다.**

```
ManagedTask.detachFromParent(lastKnownDueAt:reason:)
  └─ 호출: TaskEditorView.apply(to:) — TaskLinkPolicy.decideOnSave 의 판단을 따를 때만
```

이유를 인자로 강제한다. `TaskLinkPolicy.DetachReason` 에는 케이스가
`userChoseFixedDate` 하나뿐이고, 새 이유를 들이려면 케이스를 더해야 해서
리뷰에서 눈에 띈다. 끊긴 사실은 `os.Logger` 로 콘솔에 남는다.
