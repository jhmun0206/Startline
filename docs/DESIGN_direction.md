# Startline 기능 전반 검토

작성일: 2026-10-07 · **갱신: 2026-10-08 결정 반영 (5장) · 2026-10-13 외부 채팅의 10-08~10-11 결정 반영 (5장 ⑨, 6장) · 2026-10-13 딸린 할 일 개정 (7장)**

> 3장의 결정 1·2·3은 모두 **A로 확정**됐다. 1·2장 표의 판정도 그에 맞게 고쳤다.
> 세부 설계(특히 반복 준비 체크리스트)는 `docs/BACKLOG.md` 해당 항목이 원본이다. 이 문서는 요약만 둔다.

## 검토 기준

| | 내용 |
|---|---|
| **정체성** | 일정과 그 준비를 함께 챙기는 캘린더 |
| **원칙 0 (신설)** | 캘린더와 할 일 앱은 쉬워야 쓴다. 계산·설정·상태가 늘어나는 기능은 그만한 이유가 있어야 한다 |
| **알림 모델 (변경)** | 마감 + 사용자가 고른 「시작 알림」(3시간 전, 1일 전, 직접). 앱이 소요시간으로 계산하지 않는다 |

판정은 다섯 가지다.
- **핵심:** 정체성 그 자체
- **유지:** 그대로 둔다
- **단순화:** 남기되 줄인다
- **보류:** 지금은 손대지 않는다
- **제거:** 새 방향에서 이유가 사라졌다

## 3. 정해야 할 것

### 결정 1. 할 일의 「진행 중」 상태를 남길까? — **A 확정 (BL-066, `e5bb171`·`4a86d53`)**

지금 할 일은 상태가 넷이다: 미시작 / 진행 중 / 완료 / 놓침. 「지금 시작」을 누르면 진행 중이 되고, 시작 시각이 기록된다.

- **A. 완료 / 미완료 둘로 줄인다 (추천).** 체크박스 하나면 된다. 「지금 시작」·「미시작으로 되돌리기」 메뉴와 알림 버튼이 사라지고, BL-064도 함께 정리된다. 진행 중 상태는 원래 소요시간 보정용 데이터를 모으려고 있던 것이다.
- **B. 남긴다.** 며칠짜리 준비에는 「손은 댔다」를 표시하는 의미가 있다.

### 결정 2. 매주 반복되는 일은 어떻게 다룰까? — **A 확정 (BL-068, 설계만 · 5장 ⑦)**

예: 매주 일요일 24시 강의 마감, 매주 수요일 정기 미팅과 그 준비.

- **A. 반복 일정에 준비를 붙이면 매 회차 자동으로 생긴다 (추천).** 「강의 마감」을 매주 반복 일정으로 만들고 「3시간 전 시작」 할 일을 붙인다. 할 일에 따로 반복 기능을 만들 필요가 없고, 정체성 B와 정확히 맞는다. 대신 회차별 완료 체크를 어떻게 저장할지 설계해야 한다(BL-019). 일정 반복 입력(BL-025)도 함께 필요하다.
- **B. 할 일 자체에 반복 기능을 따로 만든다.** 일정 없이 반복되는 할 일(예: 매주 분리수거)까지 다룰 수 있지만, 반복 규칙이 일정과 할 일 두 곳에 생긴다.

### 결정 3. 「1일 전」 알림은 몇 시에 울릴까? — **A 확정 (5장 ③)**

- **A. 마감 시각에서 정확히 24시간 전 (추천).** 계산이 없고 예측하기 쉽다. 마감이 24시면 전날 24시에 울린다.
- **B. 그날 아침 9시.** 기준값이 다시 생긴다.

A로 가면 「N일 전」 칩에서 늦은 밤 알림이 생길 수 있다. 쓰면서 불편하면 그때 다시 본다.

## 5. 2026-10-08 결정

### 할 일과 알림

**① 「늦음」 배지는 마감이 지난 뒤(`isMissed`)에만 단다.**
알림이 울렸지만 마감 전인 할 일은 **주황 「오늘 시작」 배지**를 달고, 그리드 막대도 주황이다.
(10-08 에는 「알림 날짜 배지는 만들지 않는다」였으나, 10-10 3a 화면을 보고 이 배지를 유지하기로 바꿨다.
회색 줄에 같은 말이 반복되던 것은 3d 에서 뺐다.)

**② 시작 알림 입력 (BL-065)**
- 라벨은 **「시작 알림」**. 「언제까지」(마감) 칩과 구분한다.
- 칩: **[30분] [1시간] [3시간] [1일] [3일] [직접] [없음]** — **2026-10-13 개정 (`b8e815e`)**
  - 자주 쓰는 값은 **한 번 누르면 끝**난다. [직접]은 숫자 + 단위(분/시간/일)를 아랫줄에 연다
  - 범위: 분 1~1440, 시간 1~72, 일 0~365. 벗어나면 저장 버튼을 끄고 이유를 한 줄 보여준다 (BL-016)
  - **스테퍼는 쓰지 않는다**
  - 개정 이유: 10-08 안([시간] [1일] [2일] [3일] [직접] [없음], [시간]=정수 시간)은 실사용에서
    [시간]을 누르고 숫자를 다시 쳐야 해 예전 소요시간 칩보다 불편했고, 분 단위(30분)를 쓸 수 없었다.
    이를 위해 `LeadTime.fixedMinutes`(N분 전)를 추가했다
- 칩 아래에 작고 흐린 색으로 미리보기 한 줄: 「10월 11일 (토) 오후 8:59에 알림이 울려요」. 「없음」이면 줄을 숨긴다.
  시각 형식은 ⑪을 따른다.
  - 알림 시각이 이미 지났으면 「알림 시각이 이미 지났어요」를 띄운다. **저장은 막지 않는다.**
- **기본값은 3시간.** 할 일 시트와 일정 폼 초안 행이 같다. (10-13 개정 — 처음엔 1일이었다.
  새 할 일의 기본 마감이 오늘 23:59 라, 1일이면 처음부터 「알림 시각이 이미 지났어요」가 떴다)
- 칩에 없는 기존 값(옛 `durationBased` 30분 등)은 **「30분 전 (기존 값)」** 칩으로 선택된 채 보여주고,
  사용자가 다른 칩을 고르기 전까지 값을 그대로 둔다. (원칙 1)
- 모든 값은 **마감 기준 상대 오프셋**이다. 「직접」도 N일 같은 상대값이다. 절대 날짜 알림은 없다.
  그래서 반복 준비의 틀에도 그대로 쓸 수 있다.
- 할 일 시트의 옛 안내 「…에 시작해야 해요」(`StartMomentText`)는 이 미리보기 줄로 바꾸면서 없앤다.

**③ 「N일 전」 = 정확히 N×24시간.** (결정 3 A, BL-022)
지금 `fixed(days:)` 는 캘린더 연산이라, BL-065 에서 `N × 86400초` 로 바꿔 `offsetFromParent` 와 기준을 맞춘다.
한국 시간대는 서머타임이 없어 기존 알림 시각은 바뀌지 않는다.

**④ 옛 데이터는 읽을 때 해석한다. 저장값은 고치지 않는다.** (원칙 1)
- `durationBased`: 그대로 두고 읽을 때 오프셋으로 해석한다. 칩으로 표현할 수 없는 값은 `preservedLeadTime` 으로 보존한다.
  실제 스토어에 30분짜리 2건이 있어서, `fixedHours` 로 옮기면 알림 시각이 바뀐다.
- `inProgress`: `isCompleted` 하나로 해석한다(완료가 아니면 미완료).
- **enum 케이스(`inProgress`·`missed`·`durationBased`)를 지우지 않는다.** SwiftData 가 원시 문자열로 저장하고 있어 지우면 그 행을 읽지 못한다.

**⑤ 그리드 표시 범위: 할 일은 시작 알림 날짜부터 마감까지 그린다.** (옛 규칙 「착수일에 표시」를 대체)

### 순서

**⑥ BL-040 되돌리기를 P1로 올리고 BL-068 보다 먼저 배포한다.**
반복 준비가 들어오면 일정을 지울 때 딸린 미완료 준비도 함께 지워진다. 지금까지는 일정을 지워도 할 일이 남아
실수를 회복할 수 있었는데, 그 안전망이 사라진다.

### 반복 일정의 준비 (BL-068 · 설계만, 구현은 나중)

**⑦ 회차마다 실제 할 일 레코드를 만든다. 틀(템플릿) 레코드는 화면에 보이지 않는다.**
구현할 때 9개 항목을 **모두** 적용하고 테스트한다. 전문은 BACKLOG BL-068 에 있다.

| # | 항목 | 요지 |
|---|---|---|
| 1 | 재생성 금지 | 지운 회차는 「생성 제외」로 기록. 완료한 회차도 다시 만들지 않는다. 회차 처리 기록은 지우지 않는다 |
| 2 | 중복 생성 금지 | 생성 키 = 「틀 ID + 회차 키」. 같은 키는 몇 번 요청돼도 하나(멱등) |
| 3 | 개별 수정 보호 | 틀을 「이후 모두」로 고치면 안 지난 미완료 복사본에 적용. 제목·마감·알림을 따로 고친 복사본은 제외 |
| 4 | 생성 범위 | 가까운 범위(알림이 30일 안) ∪ 화면 범위(준비 막대가 그리드에 걸림). 사이를 전부 채우지 않는다 |
| 5 | 알림 없음 | 생성 기준은 준비 마감. 화면에서 숨긴다는 뜻이 아니다 |
| 6 | 앱 안에서 삭제 | 한 회차 / 이후 모두 → 그 범위의 **미완료** 준비 삭제. 완료한 건 남긴다. 확인창: 「미완료 준비도 함께 지워지고, 이후 준비는 만들지 않아요. 완료한 건 남아요.」 |
| 7 | 「이후 모두」 ≠ 틀 삭제 | 틀에 종료 경계를 기록하고 과거 복사본의 출처를 보존한다 |
| 8 | 일정 반복 입력 (BL-069) | 「안 함 / 매일 / 매주 / 매월」 칩 + 「다음 일정: 3월 31일」 미리보기. 31일 매월 반복은 실제 EventKit 결과로 테스트 |
| 9 | 알림 재채움 (BL-033) | 날짜 변경·잠자기 해제·일정 변경·주기 실행 때 재조정. 창을 닫아도 앱은 실행 유지. 문구는 「보장」이 아니라 「앱이 실행 중이면 계속 갱신, 종료 중에는 이미 예약된 알림만 유지」 |

- 완료한 복사본은 부모가 옮겨져도 따라가지 않는다. 당시 시각과 내용을 보존한다.

### 부모 일정·회차를 못 찾았을 때

**⑧ 「없다」는 이유만으로 준비를 지우지 않는다.** 날짜가 옮겨진 회차를 삭제로 오인할 수 있다.
- 연결과 준비 데이터를 유지한다
- 그 준비의 알림은 **보류**하고 「연결된 일정을 확인할 수 없어요」를 표시한다
- 다시 찾으면 날짜를 따라 옮기고 알림을 다시 예약한다
- 독립 할 일 전환은 사용자가 직접 할 때만 한다
- 일반(비반복) 일정에 붙은 할 일도 같은 규칙으로 통일한다 → **BL-070 (P2 제안)**.
  지금은 연결 유지·복구는 되지만 알림 보류와 문구가 다르다.
- 진짜 삭제인지 자동으로 가리는 것은 별도 → **BL-071 (P3)**

### 일반(비반복) 일정 삭제

**⑨ 앱 안에서 일정을 지우면 딸린 미완료 준비를 함께 지운다. 완료한 준비는 남긴다.** (반복 일정 ⑦-6과 같은 규칙)
- 질문을 늘리지 않는다. 기존 삭제 확인창에 한 줄만 붙인다.
- 근거: 일정을 옮기면 준비가 따라가듯, 지울 때도 따라가야 일관된다. 독립 전환만 하면 휴강 주의 「강의 듣기」처럼
  의미 없는 할 일이 남고 알림까지 울린다.
- **앱 밖에서 사라진 경우는 별개다.** 지우지 않고 ⑧ 규칙(연결 유지 + 알림 보류)을 따른다.
- 지금 코드는 「연결된 할 일 N개는 삭제되지 않고 남습니다」이고, 명세서 4.2 는 「독립 할 일로 전환」이다.
  **둘 다 이 규칙으로 바뀐다.** 구현은 BL-040(되돌리기)이 들어간 뒤에 한다 — 그 전에 바꾸면 안전망 없이 지워진다.
- 출처: 외부 채팅 10-08 (Perplexity 검토 요청서 3.4에서 단일 일정도 같은 규칙으로 적었고 「(다) 방식」으로 확정).

### 아직 정하지 않은 것

- **BL-040 의 범위.** 되돌리기를 BL-068 앞에 둔 이유는 「일정을 지우면 딸린 미완료 준비가 함께 사라진다」이다.
  그러니 최소한 **일정 삭제와 그에 딸린 할 일 삭제를 한 덩어리로** 되돌릴 수 있어야 한다.
  할 일만 되살리면 부모 일정이 없어 다시 의미 없는 할 일이 된다. 따라서 EventKit 일정 복원과
  `parentEventID` 재연결(다시 만든 일정은 식별자가 바뀐다)이 들어가야 한다는 쪽으로 기울어 있다.
  일정 생성·수정까지 되돌릴지는 정하지 않았다.

## 6. 2026-10-10 ~ 10-11 결정

외부 채팅에서 정하고 문서에 옮기지 못했던 것. 2026-10-13 에 옮겼다.

**⑩ 「30분 미루기」는 마감까지 남은 시간과 관계없이 항상 보여주고 막지 않는다.** 마감을 넘겨 미뤄도 허용하고,
미뤘다는 사실만 표시한다. 사용자가 직접 누른 것이라 앱이 막지 않는다(원칙 1). 「마감 30분 전이면 버튼 숨김」안은 기각.

**⑪ 시각 형식: 앱 전체를 macOS 시스템 설정의 12/24시간을 따르는 짧은 형식으로 통일한다.** (커밋 3f-2)
- 24시간 설정이면 「16:15」, 12시간 설정이면 「오후 4:15」
- `DateFormatter` 템플릿으로 만든다. 형식을 하드코딩하지 않는다. 앱에 설정을 새로 만들지 않는다(원칙 0)

- 근거: 같은 패널에서 일정 카드는 「16:15 — 22:15」, 할 일은 「오후 4시 15분」으로 섞여 있었다

**⑫ 그리드 칸 안 할 일 순서는 위에서 아래로 읽을 때 우측 패널과 같게 한다.** (커밋 3f-1)
미완료가 위, 완료가 칸 맨 아래. 「일정은 위, 할 일은 아래」 레인 배치는 그대로 두고 **할 일 묶음 안의 순서만** 바꾼다.
같은 데이터를 두 곳에서 다르게 보여주면 안 된다.

**⑬ 알림 문구.** 제목 「시작할 시간이에요」, 본문 「'제목' (부모) — 마감 …」. 계산이 없어졌으니 사실(마감)만 말한다.

**⑭ 알림 버튼이 macOS 「옵션」 메뉴로 묶이는 것은 그대로 둔다.** 실측 결과 버튼 2개면 묶이고, 거슬리지 않는다. (BL-073 종결)

**⑮ 배너:** 오늘 할 일이 원래 없던 날은 「다 마쳤어요」가 아니라 「오늘 시작할 일이 0개예요」.
「마쳤다」는 원래 할 일이 있었을 때만 말한다.

**⑯ 일정 카드 안 딸린 할 일도 「미완료 먼저」 정렬.** 같은 패널에 정렬 규칙이 둘이면 언젠가 어긋난다.

## 7. 2026-10-13 결정 — 딸린 할 일은 「일정 기준 알림」 하나만 고른다

### 왜 바꾸나

「일정에 맞춰」 할 일에는 칩 줄이 둘 있었다.
- **언제까지:** 부모 일정 시작 기준 「N일 전까지」 → 할 일 마감
- **시작 알림:** 할 일 마감 기준 「N시간 전」 → 알림

같은 말투(「1일 전」)인데 기준이 다르고, 계산된 마감은 화면 어디에도 보이지 않았다. 13일 종일 일정 + 「1일 전까지」 +
「3시간」이면 알림이 11일 밤 9시가 되어, 시트를 열자마자 「이미 지났어요」가 떴다. 두 단계를 거쳐 알림을 정하는 사람은
드물다. (원칙 0)

### 결정

**⑰ 딸린 할 일은 일정 기준 알림만 고른다. 할 일의 마감은 일정이 정한다.** 애플 캘린더의 알림 방식을 따른다.

| 부모 일정 | 할 일 마감 | 알림 칩 | 기본값 |
|---|---|---|---|
| **시각이 있는 일정** (미팅 14:00) | 일정 시작 | [30분] [1시간] [3시간] [1일] [3일] [직접] [없음] — 마감 기준 | **1일** |
| **종일 일정** (13일 접수일) | **그날 밤 23:59** | [당일 오전 9시] [1일 전 오전 9시] [3일 전 오전 9시] [직접] [없음] | **당일 오전 9시** |

- 종일 일정의 마감을 그날 끝으로 두는 이유: 접수일·생일처럼 **그날 하는 일**이 흔하다. 0시로 두면 그날이 되자마자 「늦음」이 붙는다.
  일정 전 준비든 당일 할 일이든 그날이 지나야 늦은 것이다.
- 「오전 9시」는 옛 9시 규칙(앱이 계산한 착수 시각을 몰래 9시로 옮김)과 다르다. 종일 일정에는 시각이 없으므로
  **칩 이름 자체에 시각이 적혀 있고 사용자가 고른다.** 애플 캘린더 종일 일정의 기본 알림도 「당일 오전 9시」다.
  저장은 `LeadTime.morning(daysBefore:)` — 마감 날짜에서 N일 전 날의 09:00.
- 종일 일정의 [직접]은 「N일 전 오전 9시」다(0~365일).
- 「특정 날짜」 할 일은 그대로다 (5장 ②, 기본값 3시간).
- 화면에 마감을 한 줄로 보여 준다: 「일정 시작 전까지」 / 「10월 13일 (화) 하루 안에」.
- 여러 날 종일 일정은 **첫날 밤**까지다.

### 저장

- 모델은 그대로다. 마감 = 부모 시작 + `offsetFromParent`. 새로 만드는 할 일은 시각 일정이면 0, 종일 일정이면 +23시간 59분을 저장한다.
  연결 판단(`TaskLinkPolicy`)은 바뀌지 않는다.
- **기존 할 일의 「N일 전까지」 값은 고치지 않는다.** (원칙 1) 그런 할 일을 열면 「마감: 일정 N일 전 (기존 값)」을 한 줄로 보여 준다.
- 부모가 나중에 종일 ↔ 시각 일정으로 바뀌면 저장된 오프셋이 그대로 적용된다. 드문 경우라 그대로 둔다.

### 잃는 것

- **일정보다 앞선 중간 마감**(「시험 2주 전까지 원서 접수」)은 표현하지 않는다. 알림은 2주 전에 울리지만 「늦음」은 시험 날에 붙는다.
  모델에 오프셋이 남아 있어 나중에 「마감 따로 정하기」를 접힌 옵션으로 붙이기 쉽다. → **BL-079**, 2주 써 보고 판단.

### 순서

**5a** 할 일 시트의 「일정에 맞춰」 → **5b** 일정 폼 초안 행(같은 칩, 같은 규칙).
