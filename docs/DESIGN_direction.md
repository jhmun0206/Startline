# Startline 기능 전반 검토

작성일: 2026-10-07

## 검토 기준

| | 내용 |
|---|---|
| **정체성** | 일정과 그 준비를 함께 챙기는 캘린더 |
| **원칙 0 (신설)** | 캘린더와 할 일 앱은 쉬워야 쓴다. 계산·설정·상태가 늘어나는 기능은 그만한 이유가 있어야 한다 |
| **알림 모델 (변경)** | 마감 + 사용자가 고른 「시작 알림」(3시간 전, 1일 전, 직접). 앱이 소요시간으로 계산하지 않는다 |

판정은 다섯 가지다.
- **핵심:** 정체성 그 자체
- **유지:** 그대로 둔다
- **단순화:** 남기되 줄인다
- **보류:** 지금은 손대지 않는다
- **제거:** 새 방향에서 이유가 사라졌다

## 1. 이미 있는 기능

### 일정–준비 연결 — 핵심

| 기능 | 판정 | 메모 |
|---|---|---|
| 일정에 할 일 붙이기 (상대 마감, 「3일 전까지」) | **핵심** | 정체성 그 자체다. 애플 캘린더와 미리 알림에는 없다 |
| 부모 일정이 옮겨지면 할 일도 따라감 | **핵심** | |
| 부모 일정 삭제 시 할 일을 독립으로 전환 | 유지 | |
| 일정 폼 안에서 준비 할 일 바로 적기 (초안 행) | **단순화** | 지금은 소요시간 칩과 「N일 전까지」 칩이 같이 있다. 「N일 전까지」 + 시작 알림 하나로 줄인다 |
| 미니 캘린더로 부모 일정 고르기 | 유지 | |
| 그리드에서 부모–자식 함께 강조 | 유지 | |

### 할 일 입력과 알림 — 단순화

| 기능 | 판정 | 메모 |
|---|---|---|
| 소요시간 칩 + 착수일 역산 | **제거 → 시작 알림 칩으로 교체** | 모델의 `fixedHours`(N시간 전)와 `fixed(days:)`(N일 전)가 이미 있다. UI만 바꾸면 된다(BL-018). 기존 `durationBased` 데이터는 값을 그대로 「N시간 전」으로 읽으면 계산 결과가 같다(원칙 1 위반 없음) |
| 「같은 날이면 시각, 다른 날이면 날짜」 표시 규칙, `StartMomentText` | **단순화** | 시작 알림 시각을 그대로 보여주면 된다. 규칙이 필요 없다 |
| 다른 날이면 아침 9시로 옮기는 알림(`notifyMoment`) | **제거** | 사용자가 고른 시각에 울린다. 「1일 전」의 기준 시각만 정하면 된다(아래 결정 3) |
| 알림 3단계 (예고 −1일 / 착수 / 위험 +1시간) | **1단계로** | 예고는 사용자가 「1일 전」을 고르면 되고, 위험 단계는 이미 철회했다 |
| 롤링 스케줄러 (60개) | 유지 | 할 일당 알림이 1개로 줄어 한도 부담이 3분의 1이 된다 |
| 알림의 「지금 시작」/「30분 미루기」 | **결정 필요** | 아래 결정 1 |
| 「오늘 시작」 배너 (개수만) | 유지 | 시작 알림 날짜 기준. 이름은 그대로 둔다 |
| 「기한 지난 할 일」 섹션 | 유지 | |
| 할 일 우클릭 메뉴 | **결정 1에 따라** | 「지금 시작」·「미시작으로 되돌리기」가 상태 모델에 묶여 있다 |

## 3. 정해야 할 것

### 결정 1. 할 일의 「진행 중」 상태를 남길까?

지금 할 일은 상태가 넷이다: 미시작 / 진행 중 / 완료 / 놓침. 「지금 시작」을 누르면 진행 중이 되고, 시작 시각이 기록된다.

- **A. 완료 / 미완료 둘로 줄인다 (추천).** 체크박스 하나면 된다. 「지금 시작」·「미시작으로 되돌리기」 메뉴와 알림 버튼이 사라지고, BL-064도 함께 정리된다. 진행 중 상태는 원래 소요시간 보정용 데이터를 모으려고 있던 것이다.
- **B. 남긴다.** 며칠짜리 준비에는 「손은 댔다」를 표시하는 의미가 있다.

### 결정 2. 매주 반복되는 일은 어떻게 다룰까?

예: 매주 일요일 24시 강의 마감, 매주 수요일 정기 미팅과 그 준비.

- **A. 반복 일정에 준비를 붙이면 매 회차 자동으로 생긴다 (추천).** 「강의 마감」을 매주 반복 일정으로 만들고 「3시간 전 시작」 할 일을 붙인다. 할 일에 따로 반복 기능을 만들 필요가 없고, 정체성 B와 정확히 맞는다. 대신 회차별 완료 체크를 어떻게 저장할지 설계해야 한다(BL-019). 일정 반복 입력(BL-025)도 함께 필요하다.
- **B. 할 일 자체에 반복 기능을 따로 만든다.** 일정 없이 반복되는 할 일(예: 매주 분리수거)까지 다룰 수 있지만, 반복 규칙이 일정과 할 일 두 곳에 생긴다.

### 결정 3. 「1일 전」 알림은 몇 시에 울릴까?

- **A. 마감 시각에서 정확히 24시간 전 (추천).** 계산이 없고 예측하기 쉽다. 마감이 24시면 전날 24시에 울린다.
- **B. 그날 아침 9시.** 기준값이 다시 생긴다.

A로 가면 「N일 전」 칩에서 늦은 밤 알림이 생길 수 있다. 쓰면서 불편하면 그때 다시 본다.

## 4. 정리하면

**없어지는 것:** 소요시간 입력, 착수일 계산, 9시 규칙, 알림 3단계, 위험·예고 단계, 캘리브레이션, 회피 감지, 첫 행동 실험, 착수 기록.

**남는 것:** 캘린더, 할 일, **일정에 준비 붙이기**, 시작 알림 하나, 기한 지난 할 일.

**새로 필요한 것:** 반복 일정에 준비 붙이기(결정 2).
