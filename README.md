# Startline

**일정과 그 준비를 함께 챙기는 macOS 캘린더.**

미팅·시험·과제 마감 같은 일정에 「그 전에 해둘 일」을 붙이면, 일정이 옮겨질 때 준비도 함께 따라가고
할 일마다 내가 고른 시점에 시작 알림이 한 번 울립니다.
Apple 캘린더와 미리 알림에는 없는 **일정–준비 연결**이 이 앱의 핵심입니다.

> 개인 프로젝트 · Phase 1 개발 중 · 개발자 본인이 실사용하며 다듬고 있습니다.

---

## 핵심 개념

### 일정에 준비 붙이기
- 할 일의 마감을 날짜가 아니라 **부모 일정 기준 상대값**(「3일 전까지」)으로 저장합니다.
- 부모 일정을 옮기면 준비 할 일의 마감도 자동으로 따라갑니다.
- 그리드에서 일정을 고르면 딸린 준비가 함께 강조됩니다.

### 시작 알림
- 알림 시각 = **마감 − 사용자가 고른 오프셋** (「3시간 전」, 「1일 전」 …).
- 앱이 계산하거나 보정하지 않습니다. 고른 시각에 그대로 울립니다.
- 알림에서 바로 「완료」하거나 「30분 미루기」할 수 있습니다.

### 상태는 둘뿐
- 할 일은 **완료 / 미완료** 두 상태입니다.
- 마감이 지난 미완료는 「늦음」과 「기한 지난 할 일」 섹션으로 따로 보입니다.

## 주요 기능

| 영역 | 내용 |
|---|---|
| 월간 그리드 | 일정은 위에서 아래로, 할 일은 시작 알림 날짜부터 마감까지 막대로 표시. 중복 일정 묶기, 캘린더 필터, 드래그로 기간 선택 |
| 우측 패널 | 선택한 날의 일정과 딸린 할 일, 할 일 목록, 「오늘 시작」 배너, 기한 지난 할 일 |
| 일정 편집 | EventKit 일정 만들기·고치기·지우기, 반복 일정 범위 선택, 일정 폼 안에서 준비 할 일 바로 적기 |
| 알림 | 할 일당 알림 1개, 롤링 스케줄러(앱당 한도 안에서 60개 유지), 30분 미루기 |
| 데이터 | 일정은 시스템 캘린더(EventKit), 할 일은 SwiftData. 변경 직후 명시적으로 저장 |

## 기술 스택

- **SwiftUI** · **EventKit** · **SwiftData** · **UserNotifications**
- macOS 14.6 이상
- 외부 라이브러리 없음

## 빌드와 실행

1. Xcode에서 `Startline.xcodeproj`를 엽니다.
2. **Signing & Capabilities**에서 본인 팀을 고릅니다.
   - App Group `group.com.ericmun.startline`을 씁니다. 다른 계정으로 빌드하면 그룹 식별자를 바꿔야 합니다.
3. 실행하면 캘린더 접근 권한과 알림 권한을 묻습니다.

`Startline/` 안의 파일은 폴더 동기화(`fileSystemSynchronizedGroups`)로 타겟에 자동으로 들어갑니다.
`.xcodeproj`를 직접 고칠 필요가 없습니다.

## 설계 원칙

0. **캘린더와 할 일 앱은 쉬워야 쓴다.** 계산·설정·상태가 늘어나는 기능은 그만한 이유가 있어야 한다.
1. **사용자 입력을 임의로 변형하지 않는다.**
2. **보정은 사용자 본인의 데이터로 설득한다.**
3. **AI는 단정하지 않고 참고값을 제시한다.**
4. **내부 용어를 화면에 노출하지 않는다.**

## 지나온 길

처음에는 「마감이 아니라 **착수일**을 관리하는 앱」으로 시작했습니다. 소요시간을 받아
`착수일 = 마감 − 소요시간`으로 역산했습니다. 실사용을 해 보니 문제가 세 겹으로 드러났습니다.

- 사용자는 소요시간을 모른다.
- 달력 시간으로 빼면 자는 시간을 무시한다.
- 분 단위 결과는 없는 정밀도를 꾸며낸다.

그래서 2026-10-07에 방향을 바꿨습니다. 계산을 없애고, **일정에 준비를 붙이는 것**과
**사용자가 고른 시작 알림**만 남겼습니다. 경위는 [docs/DESIGN_leadtime.md](docs/DESIGN_leadtime.md),
현재 방향은 [docs/DESIGN_direction.md](docs/DESIGN_direction.md)에 있습니다.
